# S5 交付与试点运行手册

本手册覆盖工程交付；机构授权、真实金标准、医学门槛签署、现场 UAT 和正式灰度仍由机构完成。所有示例中的域名、人员、版本和凭据均需替换。证据不得含可公开识别的患者信息。

## 发布材料与门禁

1. 将 `infra/deploy/pilot-manifest.example.json` 复制到机构受控目录。填写 commit、三类镜像 digest、当前数据库版本 `0007_quality`、配置摘要及所有抽取资产版本。
2. 收集环境/数据/词库授权、OIDC、安全、无障碍、负载、冻结质量集、恢复/删除/回滚、UAT、培训、值班、留存证据；在 dossier 内引用相对路径和 SHA-256。文件内容修改后必须重新评审。
3. 产品、医学、机构、运维分别填写签署人、含时区的签署时间和签署材料引用。此工具检查材料完整性与 hash，不校验签字真实性，也不能将合成报告提升为机构批准。
4. `uv run --project backend python scripts/ops/release_gate.py /secure/dossier/manifest.json`。退出码 1 表示不具备放行条件；空值、布尔伪装的数字、NaN、零分母、越界比例、缺少联系人/留存期、阻断缺陷非零均拒绝。阈值方向与单位固定，不能通过修改比较方向绕过高风险上限。
5. 本地提供的示例应返回 `ready: false`。禁止把示例置为通过来替代签署或真实测量。

## 镜像与配置

```sh
docker build -f infra/docker/backend.Dockerfile -t REGISTRY/clinical-backend:COMMIT .
docker build -f infra/docker/frontend.Dockerfile -t REGISTRY/clinical-frontend:COMMIT .
```

在受控流水线扫描基础系统包与应用依赖，推送后记录 registry 的 `repo@sha256:…`（本地 image ID 不能代替 registry digest）。Dockerfile 使用锁文件、非 root 运行，排除 `.env`、本地数据和测试产物。后端包含中英文 Tesseract；正式中文 OCR 质量仍须另行验收。前端采用 [Next.js standalone 输出](https://nextjs.org/docs/app/api-reference/config/next-config-js/output)，复制 public 与 static 资源。

`infra/deploy/.env.example` 是 Compose 镜像与路径模板；`.env.runtime.example` 是运行配置模板。将机构密钥写入受控文件，权限 0600，由机构 secret manager 投放，不提交仓库。API、Worker/dispatcher/monitor 使用不同数据库登录；OIDC session secret 相同以保证重启后的会话兼容。生产拒绝合成身份/抽取/词库、默认存储凭据、短会话/监控密钥和非 HTTPS 身份端点。网关仍仅支持已获准的零计费模型；付费预算功能不在本次放开。

Compose 只运行应用服务，依赖机构已部署的 PostgreSQL 17、Redis、私有 S3 与 HTTPS 入口。基础设施不得开放公网。网关仅绑定 loopback 18080；将机构 HTTPS 入口代理到该端口并限制入口访问。S3 开启服务端加密/版本管理及私有策略；备份也应加密且限制访问。`/internal/metrics` 不经公网入口暴露。不要从公网绕过网关直连 Next/API。

## 迁移、角色、项目与试点用户

先在同版本设施的隔离环境检查迁移。DBA 用独立迁移账号执行，运行账号无 DDL、超级用户或 BYPASSRLS：

```sh
uv run --project backend alembic -c backend/alembic.ini upgrade head
uv run --project backend alembic -c backend/alembic.ini check
psql -X -v ON_ERROR_STOP=1 -f infra/deploy/roles.sql
```

命令使用 DBA 的受控环境变量。`psql` 使用 PGHOST/PGPORT/PGUSER/PGDATABASE/PGPASSFILE；不要把密码写在命令行。DBA 创建 `clinical_api` 和 `clinical_worker` 两个独立 LOGIN，授予前者 `bljgh_api`，后者 `bljgh_worker`；均 NOSUPERUSER NOBYPASSRLS，且不能拥有表。迁移后重复执行 roles.sql 同步精确权限，不能授予 API Worker 角色。没有为生产创建 demo 身份。

初次创建项目使用 `scripts/ops/provision_pilot.py`，所需 JSON 如下，保存于受控目录。脚本用 DBA 身份执行，冲突时回滚整个事务，不覆盖现有成员。

```json
{
  "approved": false,
  "authorization": "机构批准单编号",
  "tenant_id": "机构生成的 UUID",
  "tenant_name": "机构名称",
  "project_id": "机构生成的 UUID",
  "project_name": "试点项目名称",
  "issuer": "与 OIDC_ISSUER 一致",
  "operator_id": "本次负责人的 users UUID",
  "members": [{
    "id": "users UUID", "subject": "机构 OIDC subject", "display_name": "经批准的显示名",
    "roles": ["reviewer"], "capabilities": ["documents.read", "original.read", "review"]
  }]
}
```

负责人必须在首批身份映射中。推荐按职责分配：导入人员只拥有 import/documents.read；医学审核员增加 original.read/review；数据交付人员使用 export.reviewed，草稿导出单独审批；独立二审使用 quality.review，裁决使用 quality.adjudicate。已有成员授权/撤销使用 `scripts/db/provision_member.py`（撤销传空 capabilities），全部追加审计。项目名单以发布材料里的允许列表为准，灰度通过项目成员与激活资产版本控制。

## 启停、迁移与回滚

```sh
docker compose --env-file /secure/compose.env -f infra/deploy/compose.yaml up -d --wait
```

发布前确认 `/api/v1/ready` 返回 200、监控采集成功、Worker/dispatcher 有心跳。ready 检查 DB/Redis/S3；它不代表临床质量或 Worker 就绪。API 采用单进程计数；增加副本时每副本单独 scrape 并在 Prometheus 汇总。

维护/备份/删除窗口：关闭入口；设 `MAINTENANCE_MODE=true` 并重建 API；停止 dispatcher；给在途 Worker 最长任务时限完成，随后 `stop -t 240 worker`；确认数据库无 running job；停止 API/monitor/所有其他写入进程与对象生命周期任务。维护模式阻断业务写请求和新任务领取，但不能撤销已进入事务的请求，不能代替停写操作。Outbox 保留在数据库，恢复时可重新投递，Redis 不是恢复的权威来源。

回滚优先切换已验证兼容的旧应用/模型/模板，不对活数据直接 downgrade。将上一份通过门禁的 dossier、Compose 环境及兼容记录准备好：

```json
{"approved": false, "reviewer": "", "compatible": false,
 "current_migration": "0007_quality", "manifest_sha256": "", "compose_env_sha256": ""}
```

在关闭入口后执行 `bash scripts/ops/rollback.sh PREVIOUS_MANIFEST PREVIOUS_ENV COMPATIBILITY_RECORD`。它验证 evidence、旧镜像摘要和已评审的 schema 兼容性，停止任务，切回应用；不自动恢复 Worker。确认已审核快照、原件、导出与权限后，显式启动 worker/dispatcher/monitor，再开放入口。上一版本必须先在恢复副本演练；本地维护配置回切不等于机构镜像回滚演练。若当前 schema 不兼容，保持停写并进入 DBA 恢复流程。旧镜像不能重新覆盖或重新发布不可变模板版本。

## 备份恢复

完整一致性备份使用独立 DBA（可读取全部受控表）和仅对备份目录有写权限的运维账号。需要 PostgreSQL 17 的 pg_dump/pg_restore 在 PATH。遵循 [PostgreSQL SQL dump 说明](https://www.postgresql.org/docs/17/backup-dump.html)：集群角色不包含在单库 dump 中，恢复前先准备相同角色。备份采用导出事务快照与共享表锁；对象清单前后变化或仍有运行任务时拒绝。

```sh
umask 077
uv run --project backend python scripts/ops/backup.py backup /secure/backups/NEW_ID --writers-stopped
```

保存返回的 manifest SHA-256 到独立的受控记录；不是保存到同一可篡改目录。目录包含完整数据库和原件，须先加密再异地保存，禁止提交仓库。备份频率、异地复制延迟、保留期及 RPO/RTO 由机构签署，不能套用本地秒级演练数据。

恢复只允许全新的空数据库和空私有桶。用目标地址替换受控 DATABASE_URL/S3_BUCKET；新库预备 `bljgh_api`/`bljgh_worker` 角色，不先运行迁移（dump 含 schema）。禁止恢复到原业务库。

```sh
uv run --project backend python scripts/ops/backup.py restore /secure/backups/ID \
  --writers-stopped --manifest-sha256 INDEPENDENTLY_RETAINED_DIGEST
```

恢复前检查 dump 和所有对象 hash；恢复后检查所有表完整行指纹、所有文件 hash、原件/派生产物/页图/未过期导出引用及审核快照。失败时隔离该目标，不开放入口；重新准备空库/桶再恢复。成功后 DBA 执行 ANALYZE，应用验证审核、下载、撤权及 RLS，再重建专用 Redis 队列并运行 dispatcher 恢复未完成任务。禁止让恢复副本连接原生产 Redis/S3。

恢复演练命令：`RUN_OPS_DRILL=1 uv run --project backend pytest backend/tests/integration/test_s5_drill.py`，仅允许 loopback 合成设施，随机创建/清理独立库和桶，默认使用本机 `bljgh-dev-postgres-1` 的 PG 工具；`OPS_PG_CONTAINER=''` 使用 PATH 中的 PG 工具。

## 留存与删除

项目整体退出使用 `scripts/ops/erase_project.py`。这不是日常文书编辑或自动过期删除。机构先检查用途到期、法定/研究保留例外、导出接收方、缓存、审计内容、备份到期计划，并签署 deletion plan：

```json
{"approved": false, "authorization": "批准单编号", "tenant_id": "UUID", "project_id": "UUID",
 "legal_hold": true, "backup_expiry": "包含时区的最后一份受影响备份到期时间"}
```

默认只返回各表数量：`uv run --project backend python scripts/ops/erase_project.py PLAN`。核对后在上述停写窗口加 `--apply --writers-stopped`；只有 approved=true、legal_hold=false、备份到期时间明确且位于未来才执行。工具先落地删除意图凭证，再删除该项目全部对象版本和删除标记，事务内按外键顺序删除临床/审核/导出/评测/成员等项目数据。仅临时停用不可变行触发器，外键仍生效；DBA 权限不授给普通应用。保留不含病例的项目壳、共享身份/租户及单独的哈希删除凭证。另一项目不受影响。

中断时凭证保留 in_progress，必须维持停写并使用同一计划重试；对象删除幂等。完成后删除该项目机构侧缓存/本地下载等受控副本并更新批准单。备份中的材料在签定到期时间消除；发生恢复时，必须先重放全部删除凭证对应的受控项目名单，再开放访问，防止材料重新出现。对象锁定/法定保留会使删除失败，应升级机构负责人，不绕过保留政策。日常孤立对象和过期导出可使用已有 `scripts/db/sweep_objects.py`，先预览再执行。

## 监控与值班

`infra/observability/prometheus.yml` 与 `alerts.yml` 可交给机构监控系统。监控 token 单独挂载为文件，不能放在 URL；API 和 monitor 都要求 Bearer token。API 提供固定路由模板的耗时 histogram/状态码，未匹配路由统一为 unmatched；不记录 URL 查询串、正文、患者名和资源 UUID。monitor 用 Worker 角色按作用域读取队列状态，不扩大 API 角色权限。指标包含 Broker 积压、Outbox 待投递、最老等待时间、按阶段失败数量、过期租约以及 Worker/dispatcher TTL 心跳。

告警是工程观察线，正式数值需与机构签定：

| 信号 | 处置 |
| --- | --- |
| 采集失败/依赖异常 | 主值班检查 DB/Redis/S3 和网络；只用 request_id 与错误码排查，不复制正文 |
| Worker/dispatcher 心跳缺失 | 检查进程与队列连接；恢复 dispatcher，观察租约回收，不手改 succeeded 状态 |
| 最老等待过长/过期租约 | 停止扩量；检查 OCR/模型时限、Worker 资源和 Outbox，核对是否重复执行 |
| API 5xx/P95 升高 | 保留请求 ID，检查依赖连接池、DB 慢查询；必要时维护模式并执行回滚决策 |
| 按阶段存在 failed | 在授权项目检查错误代码、重试上限与补料条件；数量是存量 gauge，不能当窗口失败率 |
| 存储/DB 容量、备份延迟 | 接入机构 PostgreSQL/S3/主机 exporter；按已签容量线和 RPO 告警 |
| OCR/模型费用与质量漂移 | 使用已有抽取用量/质量报告分母；没有完整计费就显示 N/A，不推算基础设施费用 |

告警接收端、主/备联系人和回滚负责人必须填入 dossier 的 oncall 材料；模板不向任何人自动发送消息。平台不自带机构监控服务器或告警配送服务。

## 负载、UAT、培训与灰度

`tests/performance/api_load.py` 运行有界并发负载，LOAD_SESSION 通过环境传入（不进报告）；默认混合文书列表/审核队列/身份读取。必须配置 P95 门槛，超过门槛或失败率返回非零。它不测实际模型、写入争用或生产容量；对应场景使用 S3 并发集成检查和机构真实文书测试补齐。

执行 [UAT 与培训清单](pilot/uat-training.md)。灰度按批准项目和少量成员开放：先由培训人员完成两类文书闭环，再在签定观察窗口内看任务失败/延迟、医学高风险错误、审核耗时和成本。出现跨项目泄漏、证据失配、未审核导出、恢复不一致或超过已签高风险上限即暂停；由具名负责人决定回切，留下发现、影响、时间和版本记录。观察通过且四方签署后才扩量。
