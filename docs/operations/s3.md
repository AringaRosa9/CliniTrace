# S3 工作台、审核和导出运行手册

适用：本地合成工程验证及获准环境部署准备。真实模型、中文 OCR、临床样本、词库授权与医学质量门槛仍按 FND-05/S4/S5 验收。

## 更新与启动

先停止旧 API、Dispatcher 和 Worker，执行增量迁移，再重新启动。迁移 0006 新增七张受项目 RLS 保护的台账，不修改既有抽取结果。事实修订、核对、问题处置、审核快照、数据集定义、导出清单与产物元数据均追加写，数据库触发器禁止更新/删除。

```sh
UV_CACHE_DIR=/tmp/bljgh-uv-cache bash scripts/db/migrate.sh
UV_CACHE_DIR=/tmp/bljgh-uv-cache uv run --project backend python scripts/db/bootstrap_s1.py
pnpm contracts
pnpm build
```

`bootstrap_s1.py` 只用于非生产本地初始化：为固定合成身份补齐 `review`、`export.reviewed`、`export.draft` 能力及数据库授权。不向其他已有成员授予这些能力。机构成员通过 `scripts/db/provision_member.py` 的显式成员清单配置。

S3 新增表须向 `bljgh_api, bljgh_worker` 授予 SELECT；API 需要对 fact_revisions、fact_checks、issue_dispositions、review_snapshots、dataset_definitions、export_jobs、clinical_facts、fact_relations 的 INSERT；Worker 需要对 export_files 的 INSERT。原有文书、任务、Outbox、审核范围权限继续保留。不得授予绕过 RLS 或修改不可变台账的权限。

继续使用根 README 的四进程启动方式。Dispatcher 按 Job.kind 投递 `parsing`、`extracting`、`exporting` 三个队列。`scripts/dev/worker.sh` 默认监听全部；需要独立扩容时用独立 Worker 分别指定 `-Q exporting` 等队列。升级前的只监听 parsing 的 Worker 必须更新，否则抽取和导出会停留排队。

## 操作流程

1. 在文档任务中建立同一患者/就诊，上传门诊与检验文书，完成解析与抽取。
2. 从文档详情“进入就诊审核工作台”，或 `/projects/[projectId]/reviews` 队列进入。
3. 工作台展示该次就诊全部文书。字段证据按钮定位对应文书/页码/原文；点原文块可反向选字段，同一块多事实时显示选择列表。PDF/图片使用已持久化页图，坐标随显示缩放，无须重新解析。
4. “编辑 / 排除”追加事实修订，必须说明理由；通过原文块“用作补录证据”补录。支持现有模板字段、重复实体及药物/检验子字段。证据 quote、Unicode span、页码、block、bbox、解析版本、数值/单位与时间均在服务端重新验证。不能任意填入推测剂量或精确日期。
5. 逐项确认绑定具体修订和范围版本。接受未知只能用于可豁免项；不会把 null 改成已知值。否定/未知不符、日期或结构错误必须修订。冲突、重复或低质量 OCR 可经核对并填写理由处置；不同来源事实保留。
6. 所有事实（包括有理由排除的事实）均已核对、阻断项已处置、全部关联文书有有效运行，且提交最终声明，服务端才创建审核快照。前端禁用按钮仅是提示，API 仍执行门禁。
7. 退回需填写理由和待补材料；进入 returned 并使旧确认失效。后续补料、新运行或事实修订重建待审范围。
8. 数据集按患者键、就诊 ID、文书名称、状态筛选；保存的是查询定义。统计与分页由服务端计算。默认筛选已审核。
9. 勾选记录、选择 JSON/CSV、填写用途后创建导出。默认只允许当前已审核范围；草稿必须具备 `export.draft`，并显式勾选。后台生成后在“我的导出任务”下载。

## 并发与版本

- 人工修订保留原始模型结果，追加 FactRevision。稳定 fact_id/entity_group_id 保持不变，新 revision_id 不复用。
- 就诊 advisory lock 串行化上传扩围、关联变更、抽取发布、有效运行切换、编辑、核对、处置、审核和导出冻结。导出跨多个就诊时按相同就诊顺序加锁。
- 编辑要求 expected_revision 与 expected_scope_revision；冲突返回 409。工作台保留输入并提示刷新对照，不自动重放覆盖。刷新后旧表单不能直接提交，须重新打开核对。
- 任一事实修订/排除/补录、新文书上传、有效运行切换，使整个范围的核对和问题处置重新确认。历史快照保持不变。候选抽取运行成功本身不会切换有效版本。
- 尚未抽取文书的关联更正会使新旧就诊范围失效。已抽取文书仍禁止直接改换患者/就诊，防止把既有事实移给另一患者；应重新建档/上传正确材料。
- 最终审核按 `(review_set_id, scope_revision)` 唯一并幂等；重复最终提交返回同一快照。导出创建另使用 Idempotency-Key，相同键不同请求返回 409。

## 导出与恢复

导出创建事务即冻结成员、事实修订、全部证据、关系、抽取配置、当前候选映射、审核规则版本、问题处置及审核状态。Worker 不再查询实时事实。生成中编辑不影响该文件；已失效范围不能新建默认已审核导出，但此前合法冻结的历史文件仍可在有效期内下载。

JSON 的 `records[].facts[]` 每条包含 `review_status=reviewed|draft`；`originals` 是用于对照的来源修订，不是当前有效事实集合。`excluded=true` 的记录保留以供追溯，研究分析应按该标记筛选。`normalized=null` 必须结合 missing_reason；assertion、experiencer 与缺失语义相互独立。

CSV 使用 UTF-8 BOM、标准逗号/双引号/换行转义，一行一事实修订；证据、关系、时间、成员、配置、词库候选以 JSON 列保存。所有文本列都执行公式防护（包括患者键、用途、原始值等）：前导空白/控制字符之后的 `= + - @` 或开头制表/回车/换行会加单引号。精确数值仍按字符串输出，负数也可能带保护前缀；JSON 保留原值。文件内有空值说明列。

当前每次最多 100 个审核范围、10,000 条事实。文件有效期为创建起 24 小时；只允许任务创建者在当前项目内下载，每次重新检查已审核/草稿能力、过期时间及 SHA-256，并写下载审计。研究者仅具有导出能力也能查询、取消/重试本人的导出任务，不需要导入能力。

导出复用 Outbox、租约、generation fencing 和尝试历史；旧 Worker 不得发布新一代结果。取消、重试、租约恢复不修改作为任务锚点的文书状态。失败可在任务列表重试；排队不动时检查 exporting 队列、Dispatcher 和 Worker。对象写入成功但事务未提交产生的孤儿，由巡检清理；下载失效不删除历史清单/哈希/审核快照。

```sh
# 默认只计数，不删除；检查输出后再显式执行 --apply。
uv run --project backend python scripts/db/sweep_objects.py
```

巡检覆盖超过 24 小时的孤儿对象及已过期导出文件；`--apply` 删除对象，不删除不可变台账。生产留存、清理调度和备份恢复要求仍由机构策略确定。
