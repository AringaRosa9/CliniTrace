# S1 文档与持久化运行手册

S1 使用真实 PostgreSQL、Redis、MinIO 和独立 Celery Worker。合成身份仅供本地开发；没有临床文书或患者会自动入库。机构身份源和真实数据授权仍按 ADR-0004 接入。

## 初始化与启动

```sh
pnpm install --frozen-lockfile
uv sync --project backend --frozen
cp backend/.env.example backend/.env
# 编辑 backend/.env：设置自选的 SYNTHETIC_ACCESS_CODE。
docker compose -f infra/compose/compose.yaml up -d --wait
bash scripts/db/migrate.sh
uv run --project backend python scripts/db/bootstrap_s1.py
```

管理脚本统一读取 backend/.env，也可用环境变量覆盖。默认值与本地 Compose 一致。初始化只创建应用角色、一个明确的合成身份/项目及私有桶，不创建患者/就诊/文书。脚本可重复执行。

分别在四个终端运行：

```sh
bash scripts/dev/api.sh
bash scripts/dev/worker.sh
bash scripts/dev/dispatcher.sh
pnpm dev
```

访问 [文档工作空间](http://127.0.0.1:13000/documents)，输入配置的开发访问码。网页通过同源代理读取 API；原始文件只在私有桶保存，所有列表、预览、下载都检查实时成员资格和能力。

`GET /api/v1/health` 仅检查 API 进程。`GET /api/v1/ready` 检查受限数据库角色、Redis、私有桶；不表示 Worker 已消费任务。排队未推进时检查 Worker 和投递器进程，以及任务 attempt/heartbeat。API 启动脚本关闭原始访问日志；不要在反向代理记录搜索 query、Cookie、授权头或表单。

## 身份与权限

机构接入配置：`IDENTITY_PROVIDER=oidc`、`OIDC_ISSUER`、`OIDC_CLIENT_ID`、`OIDC_CLIENT_SECRET`、`OIDC_AUTHORIZATION_URL`、`OIDC_TOKEN_URL`、`OIDC_JWKS_URL`、`PUBLIC_ORIGIN`、独立的 `SESSION_SECRET`。回调地址为 `${PUBLIC_ORIGIN}/api/v1/auth/oidc/callback`。授权码交换使用 PKCE S256；ID token 固定允许 RS256/ES256，校验签名、issuer、audience、azp、exp、iat、nonce。未知 issuer/subject 映射拒绝登录，不按令牌中的角色自动提权。

会话为 HttpOnly、SameSite=Strict Cookie；生产要求 Secure/HTTPS。写操作同时校验 Origin 和 session 内 CSRF token；前端仅内存保存 token，退出将会话摘要加入 Redis 撤销表。成员能力每次请求重新读取；项目变更与会话结束清除对应查询缓存及预览。不得将临床内容写入 localStorage。

独立能力为 `import`、`documents.read`、`original.read`、`audit.read`。角色只是展示标签，管理员不自动获得原件或导入权限。获准成员配置由管理连接执行 `scripts/db/provision_member.py`，JSON 清单包含：

```json
{
  "project_id": "已有项目 UUID",
  "issuer": "机构 issuer",
  "subject": "机构 subject",
  "display_name": "显示名",
  "roles": ["operator"],
  "capabilities": ["import", "documents.read"],
  "operator_id": "已有管理员映射 UUID",
  "reason": "经批准的项目授权记录"
}
```

先核对清单，再运行 `uv run --project backend python scripts/db/provision_member.py approved-membership.json`。变更追加审计；空 capabilities 撤销业务能力。机构环境需由 DBA 预置初始管理员与项目，不开放自助注册或默认管理员。

API 使用 `bljgh_api`，Worker 使用 `bljgh_worker`，两者 NOSUPERUSER/NOBYPASSRLS。每次事务 `SET LOCAL ROLE` 和事务局部 `set_config`，结束后无范围残留。用户/成员映射有独立 RLS；患者、就诊、版本、任务、解析及审计有项目 RLS。Outbox 仅含路由 UUID 与时间，API 无读取权限，投递器可读。迁移连接仅本地开发可使用 Compose 管理账号；机构环境由 DBA 为 API/Worker 配置只允许切换相应应用角色的独立登录账号。

## 文件与解析

上传以 64 KiB 块计算大小和 SHA-256；multipart 总流量在解析前限制为文件上限加 64 KiB 表单开销。Next 同源代理上限为 21 MiB。默认文件 20 MiB，UTF-8 TXT、电子/扫描 PDF、单帧 PNG/JPEG。扩展名与真实文件头必须匹配，空文件拒绝。初始对象写入隔离前缀；结构/加密/页数/像素检查在独立解析进程执行，失败保持隔离。只有已提交解析产物的原件允许下载。

- `quarantine/{tenant}/{project}/{version}/original`：原件，数据库版本不可变。
- `parsed/{tenant}/{project}/{version}/{artifact}/`：文本清单与逐页 PNG，解析版本不可变。
- 同项目文件哈希去重，跨项目无去重提示；同文件不同患者/就诊/类型返回 409，需明确更正关联。
- 幂等键包含操作者、项目和操作范围，摘要包含文件、文件名、类型、关联、来源、授权引用。同键不同请求 409；本阶段保留所有键，不实施可能破坏正在执行请求的 TTL 清理。
- PDF 逐页解析文字层、旋转、尺寸、归一化 bbox、阅读顺序和 Unicode code point 偏移。TXT 保留原始 Unicode 和换行（仅去 UTF-8 BOM），不猜测编码。
- 页面渲染为持久化 PNG，前端显示缩放/页码/文字块位置；不在浏览器执行 PDF 主动内容。稀疏/低质文字层、大面积扫描图或纯扫描页标记待 OCR。OCR 与事实抽取属于 S2，解析成功不是待审核。

解析在独立 Python 子进程执行；Linux 地址空间上限 2 GiB、CPU 170/175 秒，页图边长上限 1800px；父进程按任务超时终止子进程。默认页数 100、单图 40MP、任务 180 秒、Worker 并发 2、最多 3 次尝试。Python 网络接口禁用；正式试点仍须配置 OS/容器级禁网、最小文件系统和机构要求的恶意文件扫描，不能把语言级禁网视为抵抗本地代码漏洞的沙箱。

解析依赖 PyMuPDF 1.28.2（AGPL/商业双许可）和 Pillow 12.3.0；机构分发/部署前须纳入既有依赖许可审查。PDF 坐标实现依据 [PyMuPDF Page 文档](https://pymupdf.readthedocs.io/en/latest/page.html)，OIDC 校验依据 [PyJWT API](https://pyjwt.readthedocs.io/en/latest/api.html)。

## 任务恢复与对象一致性

上传资源、任务、Outbox、幂等结果、审计在同一数据库事务提交。对象存储先写入；若 DB 提交失败，确认无引用后清理，DB 状态不明则保留等待巡检。Redis 按至少一次投递；任务领取加行锁，每次尝试分配 generation，重复投递不会创建重复产物。

Worker 维护 30 秒租约和心跳，成功提交时再次检查状态、取消标记、租约和 generation。取消在运行边界协作停止；迟到结果和旧 Worker 无权发布。投递器每 3 秒处理 Outbox、恢复过期租约，重新投递超过 60 秒未领取的队列消息；耗尽尝试后保留失败代码。临时存储错误、超时和进程终止可重试，损坏/加密/格式/资源上限等语义错误要求更换原件。

孤立对象巡检默认只报告数量，不输出内容或对象名：

```sh
uv run --project backend python scripts/db/sweep_objects.py
uv run --project backend python scripts/db/sweep_objects.py --apply
```

仅删除超过 24 小时且数据库确认无原件版本/解析清单引用的对象；有引用的失败原件保留。留存期限和正式备份/恢复点由机构在 S5 确定。本阶段不自动删除临床记录或宣称已完成机构备份恢复演练。

## 验证

```sh
bash scripts/ci/check.sh
RUN_DB_TESTS=1 uv run --project backend pytest backend/tests/integration
pnpm test:s1
```

集成与 E2E 仅创建明确合成资料。须使用专用开发/CI 基础设施；E2E 会启动自己的 API/Worker/投递器，要求 13000/18000 空闲。`test:s1` 使用专门的临时测试访问码，结束后停止服务；不改变用户 .env。截图在 `docs/testing/baseline/s1-*`，失败跟踪在 `test-results/s1`。机构 OIDC 真正联调、真实文件恶意扫描、正式角色登录账号和临床样本验收不以这些合成验证代替。
