## 验证结果

- 后端单元、契约和数据库集成用例全套 **58 项通过**（18.79 秒），包含结构修复超时用量不完整和旧 Worker 回收故障。最终命令为 `RUN_DB_TESTS=1 uv run --project backend pytest backend/tests -q`。
- S2 最终 7 项集成验证通过：两类文书持久化/关系/待审核集合、显式切换与冲突、权限和失败、取消迟到结果、真实 loopback HTTP 网关协议与拒绝证据后的用量留存、S1 扫描件重新 OCR、旧 Worker 不能覆盖事实但保留已发生用量。
- 本地真实 HTTP 测试采用明确的合成响应服务器；验证网络协议和 Worker 子进程，不是实际 LLM 推理。
- `pnpm test:s1`：6 项通过，覆盖上传/患者与就诊建档/解析/关联更正/刷新/断网/会话清理与 390、768、1024、1440、1920 宽度。
- `pnpm test:s2`：1 项通过，真实数据库＋私有对象存储＋Redis＋Celery＋浏览器，完成创建抽取、证据高亮、候选切换、刷新持久化；390、768、1440 宽度无页面横向溢出。
- 前端 7 项 Unicode/坐标单元测试、lint、格式、类型检查、契约一致性与生产构建通过。
- Ruff、mypy 通过。`alembic check` 无漂移。新建临时数据库完整验证 upgrade → check → downgrade base → upgrade → check；之后删除该临时库，现有开发数据未回退。
- 已在本项目本地开发数据库执行 `0004_extractions`、`0005_measurements` 及新增角色授权。没有 Git 仓库，未创建 commit；CI 配置已更新，尚未运行远程 CI。

## 验证边界与后续验收

1. 默认 OCR/模型仍关闭，用户 `.env` 未修改。运行测试时通过临时环境显式启用合成适配器，未向外部供应方发送文书，未产生模型付费调用。
2. 当前机器只有 Tesseract `eng/osd/snum`，没有 `chi_sim`。下载官方中文语言包时发生 TLS 连接失败，因此中文扫描识别未实测。CI 已加入中文语言包依赖，但尚不能作为实际执行证据。
3. 表格恢复为 OCR 行单元格，复杂表头、合并单元格、跨页对应及清晰度变化仍需获准样本验证；低质量结果保留阻断项，不宣称医学语义自动正确。
4. 真实模型供应方、数据政策、中文 OCR 环境、获准样本及医学金标准仍依赖 FND-05。尚无字段准确率、映射质量、吞吐或临床 P50/P95 基线；合成模式的 0 token / 0 CNY 明确表示未调用模型。正式词库确认/发布仍属 S4。
5. 审核编辑、问题处置、人工确认、不可变审核快照与导出属于 S3。本阶段集合状态为 `pending_review`，不提供“已审核”或自动导出通道。已存在抽取运行的文书关联更正被阻止，后续需通过明确的范围迁移流程处理。
6. 生产 OS/容器隔离、机构批准、网络白名单、预算/价格表和试点门槛不能由工程测试代签；0 CNY 网关必须在供应方调用前执行预算约束。

复现与接入见 [S2 运行手册](../operations/s2.md)。
